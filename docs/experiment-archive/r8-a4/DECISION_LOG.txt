## 2026-10-31 — `/odom` 子坐标系契约改由里程计源决定（Route A readiness 最小修复，静态）

Route A（RTAB-Map localization + `--odometry-mode oracle`）停在 readiness 的根因不在定位链路，而在 readiness monitor 的 `/odom` 契约：`localization_status_monitor._odom` 只在 `localization_kind == 'amcl'` 时才接受 `child_frame_id=base_footprint`。Oracle 模式下真值 adapter 是 `/odom` 与 `odom → base_footprint` 的唯一发布者（wheel odometry 已移到 `/wheel/odom`），因此 wheel 契约下每个样本都被丢弃，`odom` 输入永不新鲜；AMCL 组合之所以正常，是因为它碰巧走了 `amcl` 分支。

修复只把契约来源从"定位方式"换成"里程计源"，不新增 Gate、不新增参数、不改算法/topic/TF：

- `localization_status_monitor` 从 session 已记录的 `odometry_mode` 选择期望子坐标系（`oracle` → `base_footprint`，其余及缺省 → `ackermann_rear_axle`），与 `navigation_safety_guard.on_odom` 的既有映射一致；不做双 frame 兼容，错误 frame、非法四元数、非有限位姿仍不计数、不推进 anchor 与历史。
- `integration.py` 只把既有的 `odometry_mode` 写入 `session.json`，monitor 只读该字段。
- 集成入口通过既有 `localization_monitor_source` 键，让四个 readiness probe 与 monitor 都运行 worktree 源码 monitor。安装副本（`review-fixes-20261019T041000Z-mapping-050`，`lib/cleannav_simulation/localization_status_monitor`，SHA256 `899facd26528518c03cc558a90f137425d1d5088a96e766ac955e09090d2f0a1`）只实现 wheel 契约，本轮**未改、未重建**，仍由 `RUNTIME_DEPENDENCIES.json` 约束；Startup Smoke 等无该键的入口路径不变。

未选方案：重建安装前缀里的 monitor（需要一次安全构建并重绑多份收据）、或让 monitor 同时接受两种 frame（会把 wheel/oracle 混用错误掩盖成 PASS）。身份：`SOURCE_MANIFEST.json` 67 files、SHA256 `46efe388a7404367ae605df2527ce5c474e4e47592a3c2d645154a920641615b`，`overlay_config.json` 同轮重绑；`run_static_checks.sh` rc=0、`554 passed / 0 failed`（新增 `tests/test_odometry_contract_mode.py` 14 例），`amcl_diagnostic_profile.py` rc=0 PASS，`dynamic_entry_calls=0`。Route A 动态仍 `NOT RUN`，须新授权 + 新 Run ID。证据：`cleannav-deliverables/route-a-odom-contract-20261031/MASTER_REPORT.md`。

## 2026-11-03 — 拒绝把 Keepout 核心格判据放宽到代价 253

`session-stationary-keepout-fix` 的 `local_core` 首个失败样本在滚动窗口 +x 边缘出现 5 格代价 253（非 254）。曾考虑把 `CampusEvidence` 的核心格判据从「恰为 254」放宽到「≥ 253」。**否决。**

理由是同一份代价值被两个消费者用不同阈值解释：`SmacPlannerHybrid` 的 `GridCollisionChecker::inCollision` 用 `footprint_cost_ >= INSCRIBED`（`INSCRIBED = 253.0`，`constants.hpp:64`），因此 253 对全局规划器是硬碰撞；`BoundedMPPIController` 委托的 `nav2_mppi_controller::CostCritic` 在 `consider_footprint: true` 时对 `INSCRIBED_INFLATED_OBSTACLE` 返回 `false`，253 只计 `critical_cost_`（300），硬碰撞需要 254。放宽判据会让局部控制器把车体带入禁行区内部时判据仍然 PASS，属于用重新定义 PASS 掩盖真实风险，而不是消除缺陷。

同时确认该 5 格不是掩膜缺失或泄漏：位置在行 86、列 95..99（窗口最后 5 列，Keepout 条带上边界行），同列行 87..93 均为 254，每列 254 计数比列 90..94 少一个，冻结静态地图在这些格全为 0，掩膜投影为 100，到最近 254 的距离仅 0.05 m；后续快照 origin 沿 +x 移动正好 5 格。`outside_mask=0`、`unknown_to_traversable=0` 全程成立。因此判定为单格宽、单周期的边界量化残差，判据保持 254，`test/test_keepout_core_cost.py` 把该判定钉住（254 通过；252/253/255 失败；253 只记为 `nonlethal_core_cells`）。
