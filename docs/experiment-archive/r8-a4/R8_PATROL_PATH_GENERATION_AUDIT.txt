### 2.2 算法实际工作原理（逐步）

1. **取边界多边形**（不是地图轮廓，也不是 Region Registry）：
   `boundary = largest_free_rectangle(known_free_component)['corners']`
   —— 在已知自由连通域里求**最大面积的轴对齐矩形**（最小边 ≥ 4.0 m，每个格都在 `Admin.opt_map` 已知自由内）。本次结果 **16.000 × 8.800 m = 140.80 m²**，角点
   `(-0.02429, -7.64818) → (15.97571, -7.64818) → (15.97571, 1.15182) → (-0.02429, 1.15182)`。
   **真实自由空间轮廓被尝试并否决**：`raw_free_outline_attempt = {simplify: 0.25, vertex_count: 52, area_m2: 472.66, feasible: false, reason: "No checked loop found: Not enough edge length for minimum-radius turns"}`。这是"贴边巡航"的直接来源——边界被收缩成了一个内切矩形。
2. **内缩**：`clearance = disk_radius(0.64661) + margin(0.15) + 0.02 = 0.81661 m`；
   `navigable = (region ∩ free).buffer(-0.81661)` → 约 **14.37 × 7.17 m** 的圆角矩形。
3. **内缩层级搜索**：`for inset in (0, 0.15, 0.30, 0.50, 0.75, 1.0)`，本次 `selected_inset_m = 0`（最浅即成功）。
4. **简化**：`for tolerance in (0.03, 0.08, 0.15, 0.25, 0.40)` → `simplify(tolerance, preserve_topology=True)`，CCW 归一化。
5. **圆角化（唯一的"转角平滑"）**：`rounded_loop(coords, radius, direction)`，其中
   **`radius = model.vehicle['turning_radius'] * 1.03 = 1.12 × 1.03 = 1.1536 m`**（`core.py:354`）。
   算法是**精确切线 直线-圆弧 倒角**（`distance = R·tan(|δ|/2)`），不是样条、不是 Bezier、不是 B-spline、不是回旋线。每个顶点被替换为一段**等曲率圆弧**，圆弧与直线 **G1 相切、曲率 C0 不连续**。
6. **校验**：`validate_loop()` 检查闭环、最小半径 ≥ 设定半径、相邻位姿航向步长、Footprint 在自由空间内。
7. **择优**：`max(candidates, key=length_m)`（本次唯一候选，41.0865 m）。
8. **采样与落盘**：`rounded_loop` 自身按 `step=0.025 m` 离散 → `dense_path_map`（1649 点）；`sample_path(dense, intervals=15)` → 16 个 `mission_checkpoints`。

**没有任何后处理会再平滑路线**：`route.json` 的 `dense_path_map` 就是被驱动的那条路径（§2.5 已验证 1649 点直通运行期），Registry 的 16 点只是**降采样副本**，不是驱动路径。

**关键区别**：`min_turning_r = 1.12` **不是**机械极限，而是比机械极限保守 21.7% 的配置值（1.12 vs 0.877 m）。但它是**运行期硬约束**：

```cpp
// motion_models.hpp:140-141  —— 硬投影，不是软代价
auto view = xt::masked_view(wz, (xt::fabs(vx) / xt::fabs(wz)) < min_turning_r_);
view = xt::sign(wz) * xt::fabs(vx) / min_turning_r_;
```

即 κ 被**硬裁剪**到 1/1.12 = 0.89286 m⁻¹。路线 κ = 0.86685 是它的 **97.1%**。

`core.py:38-46 vehicle()` 也直接从这个 YAML 读 `minimum_turning_radius`，所以路线生成与控制器**共用同一个 1.12**，再乘 1.03 —— 3% 是整条链上唯一的余量设计。

### 3.2 全路线曲率分析（两种方法交叉）

去重后 1649 点（相邻重复点已排除），总长 41.086491 m，最大采样步长 0.024968 m，闭环 0.0 m。

| 方法 | κ_max | R_min |
|---|---|---|
| ① 记录位姿 `dψ/ds`（中心差分） | 0.866868 m⁻¹ | 1.153578 m |
| ② 三点外接圆，span = 0.1 m（MPPI 同规则） | 0.866852 m⁻¹ | 1.153600 m |
| ②' 三点外接圆，span = 0.5 m（稳健性校验） | 0.866852 m⁻¹ | 1.153600 m |
| 解析值（R = 1.03 × 1.12） | 0.866852 m⁻¹ | 1.153600 m |

两种方法差 1.6×10⁻⁵ m⁻¹，**曲率无歧义**：整条路线只有**一个**曲率水平 0.8669 m⁻¹。

|---|---|---|---|---|---|---|---|---|---|
| 1 | 0.000–1.887 | 0.0000 | 1.8121 | 0.86685 | 1.1536 | 1.8121 | 左 (CCW +) | **0.000** | 4.8596 |
| 2 | 6.597–8.559 | 6.6717 | 8.4837 | 0.86685 | 1.1536 | 1.8121 | 左 (CCW +) | 4.8596 | 12.0596 |

- **无镜像/符号缺陷**：四个弯全部同号正曲率（左转），与 `direction='ccw'` 一致，与 A2 的独立结论一致。
- **无过小半径**：全部 1.1536 m > 1.12 m。
- **曲率突变位置**：每个切点处 κ 由 0 阶跃到 0.8669（或反向）。这是 C0 曲率（G1 几何），`dκ/ds` 在数学上是 Dirac；按 0.1 m 基线量化为 **5.43 m⁻²**（见 §3.3）。这是"弯道进入/退出缺少过渡"的定量形式。
- **闭环首尾连续性**：首尾位姿完全相同（0.0 m），首尾航向相同；路线**起点恰好是弯 1 的切点**（s=0 就在弯内，弯前直边为 0）。这是设计属性，不是缺陷，但意味着第一段 FollowPath 一开始就在弯上。

### 3.3 转向执行需求（δ、δ̇、ω、a_lat）

以 L = 0.60 m、κ = 0.866852 计：

| 量 | 值 | 对照极限 | 余量 |
|---|---|---|---|
| 转向角 δ = atan(Lκ) | **0.479607 rad = 27.479°** | Nav2 0.491809 rad | **0.012203 rad = 0.70°（2.48%）** |
| | | URDF 关节 0.60 rad | 0.120393 rad（20.07%） |
| 曲率 κ | 0.866852 m⁻¹ | 0.892857 m⁻¹ | 0.026005 m⁻¹（2.91%） |
| 半径 R | 1.1536 m | 1.12 m | 0.0336 m（3.00%） |
| dκ/ds（0.1 m 基线） | 5.43 m⁻² | 无显式约束 | — |
| dδ/ds | 3.02 rad/m | — | — |
| **dδ/dt = (dδ/ds)·v** | **0.630 rad/s** | URDF 转向关节 1.5 rad/s | 58% 余量 |
| 速度 v（曲率参考） | **0.2083 m/s**（= √(a_lat/κ)） | vx_max 0.30 | 直线上 0.30 m/s |
| 角速度 ω = vκ | **0.18055 rad/s** | wz_max 0.267857 | 32.6% 余量 |
| 横向加速度 a = v²κ | **0.037606 m/s²** | = `max_lateral_accel` 预算本身 | 由预算反解速度，故恒等于预算 |

速度参考逐行移植自 `curvature_speed_profile.cpp`（vmax=0.30、wmax=0.267857、alat=0.03760555、decel=0.25、span=0.1）：

- 弯内 v_ref = min(0.30, √(0.0376055/0.8669)=0.2083, 0.267857/0.8669=0.3090) = **0.2083 m/s**
- 直线上 v_ref = 0.30 m/s；后向制动（0.25 m/s²）使制动起点落在切点前 ≈0.1 m（支撑包络宽度）
- 与 A2 实测吻合：弯 1 实测 odom vx 0.177–0.251 m/s、|wz|max 0.1816 rad/s（要求 0.1806）→ **该半径在该速度下是可执行的**

**结论**：用最小转弯半径判断"可执行"是不够的——必须同时看 δ̇（此处 0.630 rad/s，占执行器 42%）与曲率阶跃。但本路线的**稳态**需求全部在极限内，且实测证明弯 1/2 能达到。

### 3.4 "3% 余量"的准确含义

同一个 3% 在四种口径下完全不同：

| 口径 | 计算 | 余量 |
|---|---|---|
| 半径 | (1.1536−1.12)/1.12 | **3.00%** |
| 曲率 | (0.892857−0.866852)/0.892857 | **2.91%** |
| 转向角（相对） | (0.491809−0.479607)/0.491809 | **2.48%** |
| 转向角（绝对） | 0.491809−0.479607 | **0.01220 rad = 0.70°** |
| 对照机械关节 | (0.60−0.479607)/0.60 | 20.07% |

`δ = atan(Lκ)` 在 Lκ≈0.52 处已进入饱和区（dδ/dκ = L/(1+L²κ²) = 0.60/1.270 = 0.472），所以**曲率上 3% 的余量在转向角上只剩 2.48%、0.70°**。这小于任何真实跟踪瞬态（A2 实测弯内峰值航向误差 0.45–0.51 rad）。因此：

- 作为**设计余量**：3% 不足，应至少 10–15%（R = 1.232–1.288 m）。
- 作为**本次失败的解释**：不是。同一半径下弯 1 达到了要求角速度（0.1816 vs 0.1806 rad/s），说明 1.1536 m 在 0.208 m/s 下可执行；失败发生在**分段终点落在弯内**的那一个弯（§7）。

### 4.2 空间可行性：向哪个方向偏移才真正增大半径

对**凸**（左转）90° 角，两条几何事实：

1. **向内切弯（增大圆角半径）**：路径相对角点内移，最大内移量 = R(√2−1) = 0.414R（沿对角线）。R=1.1536 时 0.478 m，R=2.4 时 0.994 m。因为内切矩形**整个内部都是已知自由**（`evidence: every cell inside this rectangle is known-free`），内切永远在自由空间内，且**离墙更远**。实测 Footprint 净空从 0.375 m（R≤1.5）**升到** 0.425 m（R≥1.8）。
2. **向外偏移**：平行曲线外移 d 会使凸角半径增加 d，但会**减小**墙净空：可用空间只有 0.81661 m 的内缩缓冲，而 Footprint 角点净空仅 0.375 m。外移 0.3 m 就把角点净空压到 0.075 m，且直接违反生成器的 `disk_radius + margin` 契约。**不采纳。**

**因此增大转弯半径的正确方向是"向内切弯"，不是"向外远离障碍"。** 这也推翻了"路线过度贴边导致转弯太紧"的直觉：两者不是同一个变量——贴边由内缩缓冲决定（0.82 m，充足），转弯半径由硬编码 1.03 决定（与地图无关）。

### 5.4 可实现的最大半径

- **几何上限**：短边 7.1668 m 必须容纳两个 90° 圆角的切线长 2·R·tan(45°) = 2R（+0.02 m 余量）→ **R ≤ 3.58 m**；此时短直边长度为 0（S_3500 已实测可行，短直边仅剩 0.167 m）。
- **Registry 契约**：全部位姿必须在内切矩形内（内切方向永远满足）；位姿数 ≤ 4096（R=3.5 时 1485 点，安全）。
- **覆盖代价**：R=3.5 时覆盖 −10.5%。
- **推荐带**：**R = 1.344–2.0 m**（转向余量 14.6%–40.7%，覆盖代价 −0.9%…−4.1%，净空 0.375→0.425 m）。
- **回旋线注意**：本轮 clothoid 用 0.005 m 积分步长产生 3061–4793 点，**SD_3000 的 4793 点会被 `_MAX_PATH_POSES=4096` 拒绝**。生产化必须把过渡段重采样到 ≥0.025 m。

### 5.5 候选侧的两个真实副作用（必须记录）

1. **路线起点会随 R 移动**。`rounded_loop` 把起点放在第 1 个切点，R 增大时该点沿底边后移：R=1.344 时起点偏离原 entry 0.1904 m，R=2.4 时 1.2464 m。Registry 校验 `dense[0]` 必须等于 `entry_pose`（≤0.05 m），因此**任何半径改动都必须同时重生成 entry_pose 与 Registry**（GOTO 目标点随之改变）。
2. **候选路线全部通过 Registry 的几何约束**：区域内越界位姿 0 个、闭环 0 m、首末点重合。


## 6. 第五部分：MPPI 与路线几何的协同

### 6.1 MPPI 如何读取路径曲率

| 环节 | 实现 | 参数 |
|---|---|---|
| 曲率参考路径 | `curvature_path_`（R7 独立预瞄路径，**2.4849 m / 101 poses**） | `docs/R7_REVIEW_AND_NEXT_PLAN.md:16` |
| 曲率估计 | 三点外接圆，±span 窗口 + **支撑半径包络**（取窗口内 max|κ|） | `curvature_speed_profile.cpp:17-40`，`curvature_span=0.1` |
| 速度参考 | `v = min(vmax, √(alat/|κ|), wmax/|κ|)` | 同上 :42-45 |
| 前向减速 | 后向传播 `v[i-1] ≤ √(v[i]²+2·decel·ds)` | `decel=0.25` |
| 后向加速 | 前向传播同一公式 | 同上 |
| 参考提案 | `addPathGuidedSample()` 用同一 profile 生成 1 条可行提案 | `optimizer.cpp:228-255` |
| 硬约束 | Ackermann 投影 κ ≤ 1/1.12 | `motion_models.hpp:140-141` |

### 6.2 曲率预瞄/时域是否合理

- 预瞄 2.4849 m ≈ **1.37 个圆角弧长**（1.8121 m），足以在进入弯前完成制动（0.25 m/s² 从 0.30 降到 0.208 只需 0.093 m）。**合理**。
- 支撑包络 0.1 m 使制动起点落在切点前约 0.1 m。**合理且必要**——否则三点圆跨越曲率阶跃会产生平均化延迟。
- 时域 `time_steps=50 × model_dt=0.1 = 5 s`，在 0.208 m/s 下覆盖 1.04 m ≈ **0.57 个弯弧**：足够覆盖弯内，但**看不到弯出口**。这就是"曲率阶跃 + 分段终点在弯内"互相放大的机理：控制器在最后 0.5 m 内既失去前方曲率参考（剩余路径变短），又有时域不足以看到弯出口。

### 6.3 曲率阶跃是否被采样分布覆盖

- 采样：`wz_std=0.16`、`batch_size=750`、`project_samples=true`。R7 复核记录：投影后约 **49.8% 采样零速、23.5% 落在曲率边界**（`docs/R7_REVIEW_AND_NEXT_PLAN.md:24`）。即"连续转弯"的控制序列在原始高斯分布中覆盖不足，靠 1 条参考提案兜底。
- 这解释了同一 R=1.1536 下：弯 1 达到 |wz| 0.1816 rad/s（要求 0.1806，**达标**），弯 2 0.1592（88%），弯 3 仅 **0.1210（67%）**。**不是几何不可行，而是段末参考/预瞄退化。**

### 6.4 若路线更平滑，能否不改 MPPI 参数就改善

**能，且不需要任何 MPPI 参数改动**，理由可量化：

| 机制 | 原路线 | R=1.344 | R=2.4 |
|---|---|---|---|
| 曲率阶跃幅度 | 0.867 | 0.744（−14%） | 0.417（−52%） |
| κ 占硬极限比例 | 97.1% | 83.3% | 46.7% |
| v_ref 在弯内 | 0.2083（被曲率限速） | 0.2226 | 0.2975（接近上限） |
| 参考提案剩余裕量 | 2.9% | 14.6% | 50.2% |
| 5 s 时域覆盖弯弧比例 | 0.57 | 0.61 | 0.75 |

曲率阶跃减小 → 三点圆/支撑包络的平均化误差减小 → 参考提案更接近真实几何 → 投影裁剪更少 → 跟踪瞬态更小。**全程无需改 vx_max/wz_max/alat/decel/N/温度/权重。**

必须说清：**这仍然是推断，不是实测**。工作区只有一个半径的动态证据（A2），没有"更大半径下跟踪误差"的实测样本。

**结论：`argmax(dist(start,·))` 在每一个半径上都落在第 3 个弯内部，而且半径越大落得越深。**

这不是巧合，是可证明的几何必然：起点在弯 1 的切点上，闭环圆角矩形上离起点最远的点必然落在**对角圆弧**上；"圆外一点到圆上最远点"就是过圆心那条射线与圆的交点，该点始终落在弧段内，即**永远在弧上**，与 R 无关。半径增大只让该点相对出口更靠前（弧变长）。

> 口径注记：A4 报告写"出口前 0.521 m"，用的是解析出口 s=22.355；本轮检出出口 s=22.430（±0.1 m 支撑窗使检出区间偏宽 0.075 m），故得 0.596 m。两者是同一事实的两种口径，不影响结论。

### 7.4 三个直接回答

1. **仅修改路线生成能否解决本次问题？** **不能。** 9 条候选全部把段 1 终点放在弯内，且半径越大越深。路线改动只能降低误差幅度，不能消除"终点处航向误差被冻结"的结构。
2. **A4 分段修复是否仍然必要？** **必要，而且与半径无关。** 它在 9 条候选上都把终点移到弯后直线（+0.65…+0.82 m）。
3. **是否需要两者同时修改？** 不需要同时。A4 单独即可消除本次失败机制；半径改善是**独立的系统性改进**，应单独验证（它自带新 route 身份、新 Registry、新 SMAC 验证）。


## 8. 第七部分：方案排序与最小改动

### 8.1 四种方案按用户给定的评价标准打分

| 标准 | A. 只修分段（A4） | B. 只改路线生成 | C. 两者同时 | D. 只调 MPPI |
|---|---|---|---|---|
| 根因覆盖 | **直接覆盖**（终点在弯内 = 冻结误差） | 不覆盖（§7.1 已证） | 覆盖 | 不覆盖（A2/A3 已排除） |
| 修改文件数 | 1（`patrol_path_segments.py`） | 1（`core.py` 常数）+ 新 route.json + 新 Registry + 新候选 | 3+ | ≥1（C++/YAML） |
| 是否 C++ | 否 | 否 | 否 | **是** |
| 是否 ROS 接口 | 否 | 否 | 否 | 否（但重建动态库） |
| 影响 GOTO | 否 | **是**（entry_pose 移动，GOTO 目标点变） | 是 | 否 |
| 影响 APP/Gateway/Mission | 否 | 是（Registry 契约、sequence 路径文件） | 是 | 否 |
| 影响安全机制 | 否 | 否 | 否 | **可能**（投影/权重） |
| 需重新构建 | **否**（纯 Python） | 否（但要重生成资产） | 否 | **是**（`safe_colcon_build.sh`） |
| 跨场景通用性 | **高**（任何闭环路线） | 中（只影响用 map-editor 生成的路线） | 高 | 低（针对本例调参） |
| 动态证据 | 需 1 次（预算 2/3 已用，余 1） | 需 1 次（另需重跑 SMAC 15/15） | 需 1 次但归因困难 | 已被 A2/A3 否定 |
| **综合** | **① 最小、最直接** | ③ 系统性改进，身份成本高 | ② 几何最优但改动面最大 | ④ 否决 |

**排序：A > C > B > D。** 其中 A 必须先做（它是本次失败的直接原因）；B 应作为紧随其后的独立轮次（系统性降低全环 4 个弯的跟踪负担，而不是为了"修本次失败"）。

### 8.2 为什么不采纳 C（同时改）作为本轮

1. 一次动态运行只能归因一次改动；同时改两处会让"到底哪个起作用"永久 UNKNOWN，而预算只剩 1 次。
2. 路线改动会把 `entry_pose` 移动 0.19 m（R=1.344），GOTO 目标、Registry、候选身份全部变化，验证面显著扩大。
3. 用户偏好是"先让路线天然符合车辆能力，再在确实存在独立终点缺陷时用 A4"。本轮结论正是"**确实存在独立缺陷，且路线改善不能替代它**"，所以两者都要做，但顺序应是先 A 后 B。

### 8.3 为什么明确否决 D（只调 MPPI）

- A2 已验证：计算超时（P99 22.19 ms、>100 ms 计数 0）、采样参数、曲率限速、L/R 符号、Keepout、costmap 时间戳、Footprint 全部排除。
- A3 已验证：终点位姿增强是控制器侧改动，16 场景 13 通过，但"自由空间近 XY 错 + yaw 错"仍 FAIL，且计算量显著增加。
- 用户本轮也明确要求保留已验证的曲率引导 MPPI、不引入 A3 的终点增强。

## 9. 最小修改方案及文件位置

### 9.1 推荐方案（A：分段规则）

**算法内容**：把 `closed_loop_splits()` 的 `far = argmax(dist(start,·))` 改为"**在离起点最远、且其前 1.0 m 落在同一直线上（弦偏差 ≤0.01 m）的样本中取最远**"，无合格候选时回退到原最远点。逐字实现见 A4 报告 §8.2（本轮已把该实现作为参考复制进 `tools/joint_split_compare.py` 并离线执行）。

4. **无需 colcon build**（纯 Python，无 C++/无 ABI 变化），从而完全避开 `safe_colcon_build.sh` 的单线程/锁成本与 OOM 风险；
5. 源码债（整个 PATROL Facade 在 worktree 无源码）单独登记，不在本轮处理。

> 这是"**为什么不建议本轮顺带修路线**"的第二个理由：路线侧源码干净但身份成本高，分段侧身份成本低但源码缺失——两者都需要一次独立、可归因的验证。

## 12. 最终回答（逐条）

**Q1 当前路线是不是过于接近车辆运动学极限？**
是，就"配置极限"而言。转角半径是 `1.12 × 1.03 = 1.1536 m` 的硬编码结果，κ 占 Nav2 硬投影极限的 97.1%，转向角只剩 0.01220 rad（0.70°）余量。但就"机械极限"而言不是：URDF 关节允许 0.60 rad，对应 0.8771 m 机械最小半径，本路线仍有 20% 余量。`min_turning_r = 1.12` 本身是比机械极限保守 21.7% 的策略值。

**Q2 3% 的转向余量是否足够？**
不足够作为设计余量：半径 3.00% / 曲率 2.91% / 转向角 2.48% / 绝对角度 0.70°，小于任何真实跟踪瞬态。但它**不是**本次失败的原因——同一半径下弯 1 达到了要求角速度（0.1816 vs 0.1806 rad/s）。

**Q3 巡航路线生成算法是否应该修改？**
应该。半径策略是 `core.py:354` 一条与地图无关的常数；把 1.03 提到 1.15–1.30（R = 1.288–1.456 m）可把转向余量提到 11%–23%，净空从 0.375 m 升到 0.425 m，覆盖仅降 0.9%–2%。但它**不能**修复本次失败（§7.1 已证 9/9 候选仍在弯内），因此应作为**独立轮次**，而不是本次修复的替代。

**Q4 向哪个方向调整路线才会真正增大转弯半径？**
**向内切弯**（增大圆角半径），不是向外偏移。内切让路径远离边界（净空 0.375→0.425 m）；向外偏移只会吃掉 0.81661 m 内缩缓冲、把 Footprint 角点净空压向 0，且违反生成器的 `disk_radius + margin` 契约。

**Q5 是否有足够的空间改善弯道？**
有，空间不是约束。内切矩形整个内部都是已知自由；几何上限 R ≤ 3.58 m（短边 7.1668 m 必须容纳 2R，此时短直边长度为 0）。推荐 R = 1.344–2.0 m。真正的约束是覆盖代价（R=3.5 时 −10.5%）与 Registry 契约（≤4096 点、全部位姿在区域内、起点=entry、闭环 ≤0.05 m）。

**Q6 是否应该先改路线，再决定 A4 分段修复？**
不应。离线证明：R = 1.154/1.232/1.288/1.344/1.5/2.0/2.4/3.0 全部候选的 `argmax` 分段点都在弯 3 内部（出口前 0.596–1.446 m），且半径越大越深；这是几何必然，不是调参问题。同时路线改动的身份成本最高（新 route.json + 新 Registry + 新 entry_pose + 重跑 SMAC + 新候选 + GOTO 目标变化）。正确顺序是**先 A4（1 次动态即可归因），再单独一轮做路线半径改善**。

**Q7 最终最小改动方案是什么？**
`patrol_path_segments.py` 的 `closed_loop_splits()`：把"离起点最远"改为"离起点最远且前方 1.0 m 为直线（弦偏差 ≤0.01 m），无合格候选回退原规则"。27 → 约 55 行纯 Python，无 C++、无 ROS 接口、无 route/Registry/地图/MPPI/安全改动、**无需 colcon build**。部署必须绕开"worktree 无源码"这一约束：新建候选前缀，只替换该文件并记录 `parent_sha256 → sha256`（沿用 R7-rc 的 `changed-source-files.json` 机制），跑既有 `test_closed_loop_segments.py` + 3 条新增边界用例，然后再申请**唯一剩余的 1 次动态授权**。

**明确不做的事**：不放宽 `yaw_goal_tolerance` 0.35；不改 `min_turning_r`；不改 MPPI 参数；不引入 A3 终点增强；不新增 Gate/Probe/包装器；不在未重生成资产的情况下改 `1.03` 常数。
