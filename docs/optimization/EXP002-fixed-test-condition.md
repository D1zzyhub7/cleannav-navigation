# EXP002 固定导航测试条件

## 实验目的
在不修改导航算法、局部代价地图频率和 Safety Lease 代码的前提下，固定当前仿真场景、地图数据库和目标，验证导航结果是否可重复。

## 固定条件
分支：ljy
Gazebo：ackermann_mcity_showcase_v2，GUI=false
RTAB-Map：cleannav_rtabmap_lidar.launch.py，使用现有 RTAB-Map 数据库
地图话题：/rtabmap/map
地图分辨率：0.05 m；本轮地图尺寸 261 x 189；地图原点约 (-1.319, -5.086)
局部代价地图：100 x 100，分辨率 0.05 m，范围约 (-2.45,-2.45) 到 (2.55,2.55)
全局代价地图：800 x 200，分辨率 0.05 m
初始 TF 检查：map 到 base_link 正常，首次记录约 (1.066,-0.492)
固定目标：map 坐标 (1.30,-0.49)，yaw=0；目标位于当前局部代价地图范围内
参数确认：local_costmap update_frequency 仍为 10.0 Hz，未修改算法参数

## 结果判断
三次导航均成功，成功率 3/3。三次起点接近但不是完全相同，原因是每次测试后机器人保持在上一目标附近；因此本轮证明了固定目标下的短距离导航可重复，但还不是严格重置仿真后的完全同起点对照。
本轮没有修改代码或参数，只新增实验记录。旧 EXP001 日志保持不变。

## EXP002 严格重置复测（追加记录）

### 执行方法
每次测试前执行 wsl --shutdown，重新启动同一 ackermann_mcity_showcase_v2 场景、同一 RTAB-Map 数据库 ~/.ros/rtabmap_lidar.db 和同一导航配置。固定目标为 map 坐标 (0.50, 0.00, yaw=0)。仅当 map 到 base_link TF 在等待窗口内出现且起点满足范围检查时才应计入有效测试。

### 结果
三次重置测试均执行了启动、TF 检查、代价地图检查和导航动作，但三次均未通过有效起点条件，因此有效样本数为 0，不用于成功率比较。
| 测试 | TF/起点条件 | 动作结果 | 耗时 | 规划/安全诊断 | 局部代价地图频率 |
|---|---|---|---|---|---|
| 1 | TF 未在规定窗口内确认；无有效起点 | ABORTED | 28 秒 | 启动期间持续等待 map 到 base_link；随后控制器 Failed to make progress | 1.667 Hz，间隔约 0.600 秒 |
| 2 | TF 未在规定窗口内确认；无有效起点 | ABORTED | 16 秒 | 未计入有效规划样本 | 约 1.64 Hz，间隔 0.600 到 0.700 秒 |
| 3 | TF 未在规定窗口内确认；无有效起点 | 超时，达到 50 秒窗口 | 50 秒 | 未计入有效规划样本 | 1.667 Hz，间隔约 0.600 秒 |

### 诊断
导航日志显示 global_costmap 在启动阶段持续报告 Invalid frame ID map；地图随后才建立。另观察到 base_scan 时间戳早于 TF 缓存，以及一次 Failed to make progress。Safety Lease 超时未观察到，但由于 TF/起点条件未满足，不能把本轮作为导航性能结论。规划调用次数、重规划次数和急停次数未可靠采集，明确记为未采集。

### 结论
本次严格重置流程验证了问题出在启动时序和定位/TF 就绪条件，而不是直接修改算法参数。没有修改代码、参数或 Safety Lease。EXP002 尚未获得 3 个有效同起点样本，下一步应单独解决 TF/地图就绪判定后再重测；本节为追加记录，旧日志保留。
